# 東京近郊版の実装状況

`feature/item-system` ではアイテムありのルールを唯一のプレイルールとして実装しています。未リリースです。ルール選択画面はなく、従来ルールはエンジン・シミュレーションの内部検証にだけ残しています。

## 配布内容

- `dataVersion`: `n02-2025-8a0970069659`、ルールセット: `tokyo-suburban-items-1`、セーブ形式: v4。
- 配布データは1,586駅、135サービス、2,142サービス停車行、3,988有向区間、山手線目標30区間です。`uiPresentation` は15事業者・134 UI路線グループ、46駅の別名、90サービス停車駅名の表示上書きを持ちます（うち22件は小さい「ヶ」を含む原綴り）。
- 大江戸線の環状・放射サービスは画面では1つの大江戸線にまとまり、都庁前などの抽選候補では2枠として表示されます。
- 旧形式または異なるルールセットのセーブは移行せず、破棄できます。

## アイテムと検証

11種類のアイテム、3枠の持ち物、1ターン1つの使用、出目の調整、満杯時の選択、効果の通知・ヒント、選択途中からの再開を実装しています。遊び方と確率は[現行ルール](rules.md)を参照してください。

S11で製品のE2Eをアイテムルールへ切り替え、実エンジンでシードとセーブfixtureを作り直しました。生成条件とデータのハッシュは `tests/e2e/fixtures/README.md` と `item-saves.provenance.json` にあります。過去の保存データは互換性のない形式・ルールを拒否する検証用に保持しています。

アイテムルールの計測・従来ルールとの比較は `.claude/docs/plans/item-system-handoff.md` のS7資料を参照してください。従来ルールの過去の計測値はアイテムルールの成績ではありません。

## ブラウザ・配信確認

S11の最終ローカル確認では、型チェック・本番ビルド・単体テスト970件が成功しました（既存の対象外1件）。Chromiumのデスクトップ・スマートフォンは合計151件成功、スマートフォン専用テストのデスクトップ側1件は対象外です。アイテム実エンジンのスモーク検証も2方針それぞれ100ゲームが完走し、エラー・上限到達はありません。100ゲームの結果は5,000ゲームの統計比較を置き換えるものではありません。

追尾用の余白が全体表示用の余白と合算され、アイテム欄のあるスマートフォンで新規ゲームのカメラ調整が失敗する問題を修正しました。カメラ調整前に余白をリセットし、再スタート時の表示範囲をE2Eで確認しています。Firefox・WebKitはCIで確認します。

Playwrightのローカル既定は2 workersです。以下の負荷・件数は従来ルールでの検証記録です。地図中心の実データテストは1・2 workersで各2回成功し、4 workersでは30件中7件・6件がタイムアウト、ブラウザ終了等で失敗しました。全体スイートは既定値で2回成功し、各回121 passed・2 project skipsでした。失敗は7 GB WSL2のソフトウェアWebGL下で並列度を上げた際に発生しています。Firefoxが `AllowWebgl2:false` となるWSL2環境では、古い `WAYLAND_DISPLAY` を外して `env -u WAYLAND_DISPLAY npx playwright test` を実行します。CIは2 workersとxvfbを使います。

ローカルVite previewでは5データ資産すべての展開後バイトが `public/data` と一致しました。JSONはgzipされますが `segments.geojson` は `application/geo+json` のまま圧縮されず、1,288,259 Bでした。Vercel上の実ヘッダー・圧縮・キャッシュ・ハッシュは、別途リリース時に確認します。
