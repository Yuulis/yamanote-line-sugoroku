# 配信とデータ更新の方針

決定日：2026-10-22（D5の残り）。背景は[提案](proposal.md)の「配信とデータ更新」にあります。

## なぜ方針が要るか

セーブには、遊び始めたときの路線データの版（`manifest.json` の `dataVersion`）とルールが記録されます。
どちらかが変わると、そのセーブは再開できません。画面には「路線データが更新されたため、このセーブデータは使えません。」などと表示されます。
1回のクリアに長い時間がかかるゲームなので、更新の頻度と知らせ方を先に決めておきます。

## 変えない範囲（凍結）

宣伝の開始後は、**次の大型更新まで**、次の3つを変えません。

| 対象 | 変わったと判断する目安 |
|---|---|
| 路線データ | `public/data/manifest.json` の `dataVersion` が変わる |
| ルール | ゲーム設定（`GameConfig`）や移動・抽選の決まりが変わる |
| セーブ形式 | `saveVersion` が変わる |

パイプラインを再実行して `dataVersion` が変わった場合も、上の「路線データ」の変更に当たります。

凍結中も続けてよいもの：

- 見た目・文言・演出・操作性の改善
- 不具合の修正（上の3つを変えないもの）
- 新しい版（路線網）の追加（既存の版のデータとセーブは変えない）

## 大型更新

凍結している変更はまとめて、大型更新として出します。

- アプリの版はマイナー番号を上げます（例：0.9.x → 0.10.0）。凍結中の修正はパッチ番号を上げます（例：0.9.0 → 0.9.1）。
- 出す前に、GitHub Releases と X で予告します。プレイ途中の人が区切りを付けられるようにするためです。
- 出したときに、GitHub Releases に変更内容と、既存のセーブが再開できなくなることを書きます。

## 例外の更新

次の場合は、大型更新を待たずに更新します。

- 進行不能：クリアできない、エラーで遊べないなど
- 権利上の問題：出典・ライセンス・表記に問題があるなど

このときは、更新理由と、既存のセーブが再開できなくなることを GitHub Releases と X で知らせます。X への投稿は作者が行います。

## 配信設定（`vercel.json`）

| パス | キャッシュ | 理由 |
|---|---|---|
| `/assets/*` | `public, max-age=31536000, immutable`（1年） | ファイル名に内容のハッシュが付くので、更新すると別のURLになる |
| それ以外（HTML、`/data/*`、アイコン、OGP、`privacy.html`） | Vercel の既定（`public, max-age=0, must-revalidate`） | 固定名のため、デプロイ後の次の訪問で新しい内容が届くようにする |

- 2回目以降の訪問では、JS・CSS（合計の大部分）をブラウザのキャッシュから読み込みます。
- 長期キャッシュにしてよいのは、ファイル名にハッシュが付くものだけです。`vite.config.ts` で出力名を変えるときは `tests/unit/vercel-config.test.ts` も見直します。
- 開いたままのページは、デプロイ後も古いデータで動き続けます。再読み込みすると新しいデータになり、そのとき古い版のセーブは上の表示で再開できなくなります。

## 未対応（必要になったら検討）

- 旧データの保持やセーブの移行（大きな設計が必要）
- ゲーム内のお知らせ表示
