# v0.22.0 リリースノート

作成日：2026-11-28。この文面は、GitHub Releases に載せる本文の元になります。v0.22.0 では、地図を見やすくしました。あわせて、クリア画面の軌跡の再生にカメラの追尾とシークバーを加えています。ルール、セーブ形式、路線データは変わりません。そのため、[配信とデータ更新の方針](data-update-policy.md)の「大型更新」には当たりません。

## 公開時の本文

### v0.22.0：地図が見やすくなり、軌跡の再生で1ターンずつ見返せるようになりました

**乗っている路線と山手線が目立つようになりました**

- ゲーム中とクリア画面の地図では、背景の路線を細く薄く描き、地名やアイコンも少し薄くしました。乗っている路線と山手線が先に目に入ります。タイトル画面の地図は、これまでどおりの見た目です。
- 抽選で路線の候補をめくっている間は、候補の路線を地図上で強調します。

**ゴールの新橋がわかりやすくなりました**

- 新橋の目印を、金色の太いリングにしました。
- 30区間をすべて踏破すると、リングがゆっくり脈打ちます。あわせて「ここに着けばゴール」の吹き出しが出ます。動きを減らす設定にしている場合、リングは脈打ちません。

**軌跡の再生でカメラが追いかけ、1ターンずつ見返せます**

- 再生中は、ターンごとにその移動の範囲へ地図が寄ります。自分で地図を動かしたり拡大したりすると、その視点を保ったまま再生が続きます。最後まで進むと、全経路を表示します。
- 再生中は、結果のカードが画面下のバーにまとまります。バーにはシークバーと「前」「次」のボタンがあり、好きなターンへ移れます。再生中にシークしても、再生は止まりません。
- 一時停止中や再生が終わったあとは、バーの「結果を表示」を押すと、結果のカードに戻ります。
- PC では、バーから「移動履歴を見る」も開けます。

**重なっていた路線が並んで見えるようになりました**

- 東海道線と横須賀線のように同じ線路を走る区間を、拡大した地図で少しずらし、並べて描くようにしました。ずれが付くのはズーム11より拡大したときで、ズーム13で最大になります。全体を見渡す倍率では、これまでどおり重ねて描きます。
- 線をずらす計算は、地図を読み込んだあとに裏で行います。拡大していると、読み込み直後の1〜2秒は、線が重なったまま見えることがあります。

**途中のセーブデータについて**

ルールとセーブ形式は変わりません。途中のセーブは、そのまま続きから遊べます。

## 変更（内部メモ）

- 地図の強弱（PR #139）
  - 背景路線は幅 2 px、不透明度 0.40 で描く。ゲーム画面とクリア画面のみで、タイトルは従来どおり。
  - 抽選中の候補路線を強調するレイヤーを追加した（`lottery-flip`・`lottery-settle` の段階のみ）。
  - ベースマップの文字とアイコンを、それぞれ 0.75 倍と 0.65 倍に薄くした。
  - ゴールリングは `#d4a017` の 5 px。30/30 区間を踏破したあとは、CSS の脈動と「ここに着けばゴール」の吹き出しを出す。
  - 色覚特性の確認は報告のみとし、公式色は変えていない。結果は `docs/manual/map-readability/colour-vision.md` にある。
- リプレイ（PR #140）
  - ストアに、再生状態を保ったままのシーク・1ターン送りと、`cardExpanded` / `showResults()` を追加した。終了後の「前」と「次」は、どちらも最初のターンへ移る。ストアの通知は購読者ごとに届けるよう作り直した。
  - カメラは `useClearReplayCamera` が担う。ターンごとに寄り、手動で操作するとロックする。明示的なシークでは1回だけ寄り直し、完了時は全経路を表示する。
  - 再生中の下部バーは PC とスマホで共通。帰属表示はバーの上へ逃がす。クリア画面の地図はポインターで操作できるが、Tab の巡回には入らない。
- 重なり区間（PR #141）
  - `corridorOffsets.ts` は、端点の座標が完全に一致する辺を共有区間として扱う。スロットは安定で、山手線が 0。
  - 派生ソースは背景・乗車中・抽選候補の3レイヤーだけが使い、`line-offset` はズーム13でスロット × 6 px。
  - 派生の計算は Web Worker で行う。適用に失敗したら元の形状に戻す。
  - 性能ゲートのうち「読み込み後に1回だけかかる処理」は基準（中央値 50 ms）を超えた（PC で中央値約 58 ms）。操作中のフレーム時間は変わらないため、作者の判断で受け入れた。記録は `.claude/docs/plans/map-readability-perf.md` にある。
- `dataVersion` は `n02-2025-7974da15af8e` のまま。ルールセットとセーブ形式も変わらない。
- 対応する PR は #139、#140、#141（Issue #72）。リリース PR に `Closes #72` を記載する。
- 新機能を含むため、アプリの版はマイナー番号で上げる（0.21.0 → 0.22.0）。

## 確認（内部メモ）

- PR #139、#140、#141 で、Chromium・Firefox・WebKit・スマホを含む CI の全項目が通過した。
- 各ステップで、`npm run typecheck`、全ユニットテスト、`npm run build`、スマホの `@layout` E2E を手元で通した。最終は 2880 passed / 1 skipped と、`@layout` 129 passed。
- 性能計測（`npm run perf:map`、5回、デスクトップとモバイル相当）では、移動フレームの P50 が 16.7 ms で変化なし。派生後の地物数は 2,518（上限 3,876）。
- 実機では未確認。公開前に次の5点を確認する。
  - スマホで、再生中の下部バー（シークバー、「前」「次」）が押しやすいか。
  - スマホで、再生中に地図をピンチで動かしたあとも、その視点が保たれるか。
  - 30区間を踏破したあと、ゴールのリングと吹き出しが見やすいか。
  - 東海道線と横須賀線の区間を拡大したとき、並んだ線が見分けられるか。
  - 読み込み直後にすぐ拡大したとき、線の切り替わりが気にならないか。
