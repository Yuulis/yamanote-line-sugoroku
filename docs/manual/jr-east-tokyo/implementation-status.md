地図形状は41,176バイトで上限300,000バイト以内です。形状端点とホーム位置の最大ずれは24.507mで上限30m以内です。東京駅の京葉線ホームは代表点から386.0m離れていますが、確認済みの500m例外内です。

固定シードのブラウザ用路線網は、乗換・方向抽選・終点・エリア端を通り15ターンでクリアすることをVitestで証明しています。実データでも8つの固定シードでクリア・途中保存の復元・クリア結果の復元を確認しました。実データの画面はPC・スマホで確認し、開始時の全ホーム位置が操作パネルに隠れないことを自動検証しています。

ローカルのWebKitは、既存設定どおり実行対象外です。GitHub ActionsのE2EにはWebKitが含まれます。生データを持たないCIでは既存の生成テストだけがスキップされ、公開データの検証と合成データのテストは実行されます。

追加の `scripts/check.sh` は9件成功・1件失敗です。今回より前からある `.claude/worktrees/` 内まで再帰検索し、そこにある検査スクリプトのコメント `${CODEX_MODEL:-...}` をモデル名として誤認します。実際のモデル設定は一致しており、アプリの必須CIとは別の既存の誤検出です。検査を緩める変更は行っていません。

## 互換性と残作業

旧セーブは移行しません。対応外の案内と削除操作が表示され、自動削除はしません。鉄道データの出典・ライセンスはN02 2025 / CC BY 4.0のままです。N03は配信データに含めません。N02では一部の並行路線が同じ線形を共有するため、すべての実際の線路を分離した地図ではありません。

[開発統合PR #3](https://github.com/Yuulis/yamanote-line-sugoroku/pull/3) で全変更を統合します。最初のCIは3必須チェックすべて成功し、その後、新規ゲームで以前のズーム位置が残るケースも回帰テストで再現・修正しました。最終コミットのCI成功後に統合し、`develop` → `master` のリリースPRを開きます。本番へのマージと本番スモークテストは承認後です。最新のPRと進捗は [.claude/docs/plans/jr-east-tokyo-expansion-handoff.md](../../../.claude/docs/plans/jr-east-tokyo-expansion-handoff.md) を参照してください。
